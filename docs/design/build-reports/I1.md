## I1 report: contract changes merged, workarounds removed

Every "Contract changes requested" item from the M0 and T1 to T5 reports is now in the shared files, and every listed workaround is gone. The full suite passes: 658 tests before I1, 676 after. No decision rule or threshold value changed. The controller still makes no config changes (its hooks are no-ops until I2), so I did not run a grade against a baseline.

### What changed
**T2 (governance)**
- `EffectivePolicy` gained `pre_open_submits`, `api_auto_enabled`, `api_allowed_dims`, `use_case` and `directive_scopes`. `approver_close_min` and `ttl_min` are now properties computed from the API fields. This removes `ExtendedPolicy` and `ext()`.
- `Proposal.p0_rank` is a field, and migration 0009 adds the column with `CHECK ((class = 0) = (p0_rank IS NOT NULL))`. This removes `evidence["p0_rank"]` and `p0_rank_of`.
- `Substitution` moved into `types.py` and `RebaseReport` gained `substitutions`, which removes `RebaseOutcome`.
- The `Overlay` and `ProposalLifecycle` protocols now include the keyword arguments and methods the implementation already had.

**T3 and T4 (learning, incidents)**
- `WorkflowSnapshot` gained `cells`, `active`, `looks`, `decay`, `holdouts`, `changes`, `end_minute`, `run_id`, `snapshot_id` and a `window` property. It now compares by identity (`eq=False`), because it holds numpy arrays.
- `LookRecord`, `HoldoutState` and `ChangeRecord` moved into `types.py`. `LearningSnapshot` and every `getattr(ws, ...)` fallback are gone.
- New settings:
  - `apply_time_trend_p` replaces `decay.TREND_SIGNIFICANCE`.
  - `winner_scope_ramp` replaces `cohortset.WINNER_SCOPE_RAMP`.
  - `look_max` defaults to 0 (no cap), and `look_due` now respects it.
  - The `decay_cusum_h` description now says about 336 segments, not 168.
- The freeze has one formula, `world.clock.freeze_start`, and both the DID prober and the cohort projection read `ws.end_minute` through it.
- `FlagMonitorState.last_sim_hour` replaces the reused `last_event_id`; migration 0010 renames the column.
- **`PatchRequest.decision_id` is optional, with this rule:** pure modules emit None; the caller writes the decision and stamps the request before `Overlay.add`, which raises if the id is missing.
- **Segment formula:** I checked it and the two rules already agreed. Ingest computes the same rule on each dial's tick start. A new test, `test_ingest_segments_follow_the_learning_rule`, compares the two on windows 9-21, 9-20 and 7-20, with both parsers.

**T1 (loop, reliability)**
- `EnvSettings` gained `stop_after_steps`, `synthetic_markers` (checked when settings load, so a bad marker exits with code 3) and `prefetch_chunks`. This removes `LoopOptions`.
- `FaultKind` gained `chunk_copy` and `bootstrap`, and `faults.KNOWN_KINDS` is now derived from it.
- REFRESH now records its progress in `config_event.refreshed_minute` (migration 0011, filled in from the old audit-row markers). Its audit row uses the `wf@vN` subject that `why-changed` starts from; the old `wf:N` form broke that chain.
- Validation and suggest-fixes intents must carry `credits_before` and `cost`. The executor refuses a request without them before writing anything.

**T5 (alerts, holds)**
- `alert.dedupe_key` with a unique index on open alerts replaces the `[subject]` message prefix. `hold.released_by` replaces the text appended to `reason`. Both are migration 0012, which also converts old rows.
- **Bug found and fixed:** the alert writer in `store/repos.py` stored NEW_WORLD as a digest with a runbook link to `#new_world`, an anchor that does not exist. It also used two codes missing from the catalogue (CLOCK_MISMATCH, INTENT_UNKNOWN).
  - I reproduced it on the old code by adding an assertion to `test_run_identity`. It failed there and passes now.
  - That writer is deleted; every alert now goes through `obs.alerts.raise_alert`. The two codes are added to the catalogue and to `docs/RUNBOOK.md`.

**ADR 0028** (`docs/decisions/0028-integration-contract-changes.md`) lists each change and why. ADRs 0002, 0012, 0013 and 0018 now point to it where they described a workaround.
