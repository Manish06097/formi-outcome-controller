## Bugs found and fixed (all outside controller/learning)
1. **why-changed "what happened after" was empty or wrong on a real run.** Reproduced with `why-changed --workflow ks_cancel --at "D3 14:00"` (no aftermath) and `--at "D3 11:30"` (days of unrelated advance intents from D1). Cause: explain.py followed `audit_log.caused_by` as an audit id; the writers store a decision id, and the real controller never writes `subject_type='proposal'` rows. Fix: aftermath joins `proposal_transition`, audit rows by subject or decision id (intents excluded), decisions and alerts naming the proposal, and for a supervisor edit the rebase, stale marks, interrupted experiment and the incident it opened. Re-run shows the D3 11:30 supervisor edit followed by rebase, stale proposal, incident fix proposal, SUPERVISOR_EDIT and EXPERIMENT_INTERRUPTED. The hand-filled audit fixture (which used audit-id semantics) was adjusted and a regression test added.
2. **why-heard reported COHORT_MISMATCH for every call under a controller version.** `allocation_provenance` was only written for business-default and supervisor versions (`world/configs.py`). Fix: `record_provenance` called from `_on_applied` with each changed (cohort, dim) attributed to its proposal, approval and decision. Verified in SQL over all 104,000 calls of the re-run: 0 missing provenance for welcome, voice, caller ID. Not recorded: `experiment_id` (the diff does not carry it).
3. **Runs were not reproducible, so crash equivalence could not be shown with the full controller.** Decision seeds used the schema name including its run counter. Two clean public_01 runs differed (28 vs 34 config versions). Fix and rationale: ADR 0033. After it, two clean runs and the crashed run match table for table.
4. Test fixture `api_dsn` had no dbname (item 3).

## Open problems and honest numbers
1. Replay covers 5 of ~50 decision kinds.
2. Overlay note says "your supervisor set X on D3 12:00" using the minute the controller saw the edit, not the edit's minute (D3 11:30); the cooldown also starts at detection. Cosmetic, in `planner/overlay.py` (`rebase_on_supervisor_edit` has no applied minute argument). Not fixed.
3. `COHORT_MISMATCH` pages fire from the 3-SE realised-share check: 1 in public_01 (3.0 SE), 1 in the first public_02 run, 3 in public_03. Chance level over many shares, but it is a page; consider requiring two consecutive failures before paging (lifecycle.py, not changed).

Outcome weak spots: `nw_renewal` in public_02 has engagement -2.1% and more hallucinated calls than baseline (65 vs 54); `nw_kyc` engagement is -2.4% (public_01) and -2.2% (public_02) with pickup as primary; public_03 hallucinated calls 4,975 vs 4,667 baseline. public_01 engagement gap captured is only 6%.

6. Decision/patch ids differ between a clean and a crashed run (identity values; patches are recreated after restart); content is identical. A crashed run has 29 more decision rows than the clean one (556 vs 527 in an earlier pair), i.e. re-made decisions after a restart.
