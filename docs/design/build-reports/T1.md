### 2. What I built, by DESIGN.md section

**Ingest (3.1, 8.1)**
- `ingest/loader.py`: a loader thread streams each chunk from httpx straight into `COPY stage_raw` in csv mode with `\x02` and `\x01` as delimiter and quote. The chunk number is prefixed to each line as the bytes stream, so a chunk is never held in memory. It stages chunk k+1 while chunk k is being transformed.
- `ingest/transform.sql`: about 30 named, timed statements in one transaction per chunk.
  - It checks the parsed count and the first and last event id against the chunk metadata.
  - History calls go to rollups and lead state only; post-D0 calls also go to `call_fact`.
  - Hour, segment and `tick_no` come from the tick start, because the simulator randomises the call timestamp inside the tick.
  - `lead_sk` is the lead event's id, so keys are identical across crashes.
  - Rollups are additive upserts.
- `ingest/python_parse.py`: the fallback parser. It fills the same typed temp table, so everything after parsing is shared SQL.
- `ingest/pipeline.py`: the `Ingestor`. It ingests chunks in order exactly once, fills gaps, retries a count mismatch once, truncates the stage after each batch, and provides `rollup_mismatches()` to recompute rollups from scratch.

**World (8.5, 4.1 step 4, 6.3, 6.7)**
- `world/fingerprint.py`: computes the fingerprint and runs every resume check in 8.5. It also checks that our newest chunk matches the simulator's chunk with that number. It then resumes the newest consistent schema, or creates a fresh one, marks the rejected candidates abandoned and raises a `NEW_WORLD` alert.
- `world/configs.py` (ConfigMirror): records bodies as ours, fetched or unknown, assigns cohort codes, effective cells and changed overlay paths, writes provenance for versions we did not write, and has `record_ours()` for governance.
- `world/clock.py`: `next_working`, the exact `p_expire` of 6.3, submit candidates and `s_watch_max`.

**Loop (4.1, 4.2)**
- `loop/stepper.py`: a pure `next_stop` and `plan_stop` covering the apply bound, the boundaries and the overnight-jump guard. `basic_policy()` is the API-only policy used until T2's registry exists.
- `loop/orchestrator.py`:
  - Runs the restart sequence of section 2 and the PLAN to OPS steps of 4.1.
  - LIFECYCLE, DETECT, DECIDE, GOVERN and VERIFY are no-op hooks on the `LoopHooks` class, which other tracks subclass. Policy and plan facts are hooks too.
  - REFRESH works from the `config_event` table, so config events ingested by a process that crashed before its REFRESH are still handled.
  - It honours pending and approved markers from the `proposal` table, plus synthetic test markers.

**Reliability, audit and ops (8.2, 8.3, 10.2, 9.1)**
- `reliability/intents.py`: `IntentExecutor` (decision and intent rows, then the call, then a second transaction), `Reconciler`, and the call and lookup for every kind in 8.3. Other tracks attach their domain hooks with `IntentRegistry.attach`.
- `reliability/faults.py`: `CTL_FAULT`, with multiple specs allowed. Each fault fires once per run and records an audit row.
- `audit/writer.py`: `write_decision`, `record` and `provenance`.
- `obs/metrics.py`: phase timer, RSS, the heartbeat thread (which exits if the advisory lock is lost) and run summaries.
- `store/repos.py`: one shared `COHORT_CODES_SQL` statement plus the helpers for the platform tables.
- `controller/__main__.py`: exit codes 0, 1 and 3.

**Packaging and scripts (11.3)**
- `Dockerfile`: the image contains only `controller/`.
- `compose.yml`, `compose.linux.yml`, `compose.desktop.yml`.
- `run.sh`:
  - Reuses this project's running db port, otherwise takes the first free port in 55432 to 55451.
  - Checks that the base images exist and pulls them if not.
  - Restarts the controller after a crash and stops on exit code 3.
- `scripts/run_local.sh`.

### 5. Deviations from the design, and why
- **Base step.** The base step of 60 never reaches the apply bound of 90 in approver hours. The bound is enforced, and the e2e test checks it with `CTL_T_BASE_STEP_MIN=180`.
- **Fixed boundary.** "Approver close + tick" is a stop boundary even when nothing is pending, as 4.2 lists it. This costs one extra step per day.
- **Proposal ids** use the fingerprint's first 6 characters, not the schema name, so two runs of one world issue identical ids.
- **Lead state.** Lead exhaustion by time is applied once per campaign, in the chunk whose `until_minute` reaches the campaign's last cadence day. A lead is also exhausted when its attempts reach the cadence total.
- **Cohort ownership.** A cohort is ours if its id contains `~`. Every other cohort, and `default`, belong to the supervisor.
- **`effective_cells`** are limited to cells seen in that workflow.
- **Rejected run candidates** are marked `abandoned` rather than left `active`.
- **`world/clock.py`** was labelled T2 in the M0 skeleton but was on my task list, so I wrote it. `routine_slots` and `choose_submit` are left for T2.

### 6. Known gaps and risks
- **Bugs found and fixed:**
  - A fault firing while another fault was armed re-entered a non-reentrant lock and hung the process mid-COPY. Found by the kill test; fixed, with a regression test.
  - Deleting staged chunks left 0.6 GB of dead rows over public_03; the stage is now truncated after each batch.
- **Linux host networking** (`compose.linux.yml`) is written but untested: there is no Linux box here.
- **Vendored wheels:** `scripts/vendor_wheels.sh` has not been run end to end. The image builds from PyPI.
- **Ingest is the slowest platform stage:** 26k to 37k events/s, below the 40k to 80k the design estimated. It slows as `lead_dim` grows. This leaves about 85 s of the 120 s per-day target for the decision stages.
- **Stale `effective_cells`:** they refresh when the global cell count changes, so a cell new to one workflow but already seen in another stays stale until then.
- **Unrun lookups:** the reconciliation lookups for `submit_approval`, `auto_apply`, `apply`, `validation` and `suggest_fixes` are implemented but have never run end to end, because no track issues those intents yet.
- **Logs:** a log line per ingested chunk is noisy at public_01 scale.
- **Cleanup:** the `formi_t1` compose Postgres is stopped; its volume is kept. The dev container is gone.
