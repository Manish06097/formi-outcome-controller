### 2. What I built

**(A) Private variants (17 override 3, 10.1, 9.7)**

  - Each file starts with a header: what it tests, what passing looks like, the DESIGN.md section, and the exact list of changes from the base.
  - `--check` reports whether any committed file is out of date. `--verify` loads every file with `sim.scenario.load_scenario`, runs `python -m sim baseline` on it, and writes the wall times.
- **Coverage:**
  - New seeds (p01 and p02).
  - Effects: sign-flipped, halved, x1.6, and flipped plus x1.3 on p02. Case (j): the only winners are the last-listed options, each helping one cohort and hurting another.
  - Decaying winner (g), at 3x volume and at dev volume.
  - Caller IDs: a DID flagged on D1, and the sole DID of nw_kyc flagged on D1. Case (h): unknown spare DIDs already at health 0.3.
  - Prompts: a P4-like supervisor prompt (halluc 0.0275), plus a 20-seed family of it for the "18 of 20 seeds" check. A P2-like supervisor prompt (halluc 0.0545). Case (i): unsafe business-default prompts on two tenants.
  - Case (e): a DID flagged while the prompt-fix approval is pending. A supervisor edit while our approval is pending.
  - Governance attacks:
    - (a) TTL 12h with latency 60-480.
    - (b) approvers 14-16 with TTL 4h.
    - (c) fatigue cap 1 with auto-apply off.
    - (d) max_shift 0.05 with a DID flagged at a one-third share.
    - prompt_version allowed for auto-apply.
    - tick 5.
    - credits 50 and 60.
  - Added beyond the list, because they were cheap: (k) 60% rejections, and the 9.7 rows (tick 30, apply window 1h, max_shift 0, auto-apply off, no history, gate 0.99, next_campaign_only everywhere, approvers 14-16 with TTL 24h).
- **Baseline wall times** are in `docs/measurements/private-variants-baseline.md`: 56 of 56 ok. Most take 2.2 to 2.9 s; tick5 takes 4.2 s, the high-volume decay 3.8 s, no-history 1.0 s.
- **`scripts/variants/run_matrix.sh`** runs the baseline and the grade for each variant you name (all by default, `--all` adds the seed family).
  - With `--controller CMD`, it serves the simulator on port 8715, runs `CMD <SIM_URL>`, and grades that run against the baseline.
  - It writes `summary.tsv`. I checked it end to end with the naive example controller.

**(B) M7 pure parts**
- **`controller/audit/explain.py` (9.4):**
  - `why_changed` follows `caused_by` chains across subjects. It flags a version that was written without one of our proposals (UNKNOWN_WRITER).
  - `why_heard` gives per-dim provenance, including inherited default rows. The prompt comes from the version live at the call minute. It uses LEFT JOINs, so a missing provenance or cohort row is reported as `COHORT_MISMATCH` instead of the call being dropped.
  - `weekly_digest` covers operational changes with their reasons.
  - Text rendering helpers.
- **CLI `python -m controller.audit`:** `why-changed`, `why-heard`, `replay-decision`, `replay-sample`, `weekly-digest`. Each takes `--json`, `--schema` and `--dsn`, and connects read-only. Exit codes: 0 answered, 1 a replay differs, 2 not found or bad argument.
- **`controller/audit/replay.py` (9.6):**
  - Replay loads the decision and its snapshots, decodes them and checks `inputs_hash`. It refits, or reuses the stored fit with `--no-refit`, then compares with a 1e-9 tolerance. It warns when settings_hash or code_version differ from the running ones.
  - The recomputation is pluggable: `register_recomputer(module, rule_id)`, found by importing the learning, incidents, governance and planner packages.
  - It also holds the snapshot codec (`encode_inputs`, `encode_array`, `hash_inputs`) and the deterministic `sample_decisions`.
- **`controller/api/app.py` and `controller/api/views.py` (9.1, 9.3):** FastAPI.
  - Endpoints: `/health`, `/supervisor/{tenant}` (all 8 sections, with pickup and engagement reported as separate numbers), `/supervisor/{tenant}/digest`, `POST /supervisor/holds` and `/supervisor/holds/{id}/release`, `/explain/change`, `/explain/call`, `/explain/decision/{id}`, `/ops`.
  - It connects as `ctl_api`, runs every read in a READ ONLY transaction, and refuses to serve (HTTP 503 with the reason) if its role can write anything but `hold` or is a superuser or the schema owner.
  - Started with `uvicorn --factory controller.api.app:create_app`.
- **`controller/obs/alerts.py` (9.2):** 28 codes, each a page or a digest item and each with a runbook anchor.
  - Condition rules are pure over `AlertInputs` (`evaluate`), read from the store by `gather_inputs`, and opened and closed by `sync`.
  - Event alerts go through `raise_alert` and are de-duplicated; digest items are recorded already closed.
- **Docs:** `docs/RUNBOOK.md` has one `<a id="CODE">` anchor per code, and a test checks the anchors and the catalog match both ways. `docs/RUNNING.md` covers running, debugging and extending, with a status table of which pieces exist today. ADR `docs/decisions/0026-decision-replay.md`.

### 4. Contract changes requested
1. **`alert.dedupe_key text`** plus `CREATE UNIQUE INDEX alert_open_key ON alert (code, coalesce(wf,-1), dedupe_key) WHERE closed_wall IS NULL`. Without it I de-duplicate on a `[subject] ` prefix in `message`.
2. **`hold.released_by text`**. Without it, release appends "[released by X at T]" to `reason`.
3. **Conventions other tracks must follow** (documented in the explain and replay module docstrings):
   - **T1 `audit/writer`:**
     - a config version's audit row uses `subject_type='config_version'` and `subject_id='<workflow_id>@v<version>'`, from `explain.config_version_subject`;
     - consequence rows set `caused_by`;
     - decisions not to act use `kind='no_action'`.
   - **T2 builder:** `proposal.evidence` keys `kpi`, `notes`, `items`, `expected_decision_window`.
   - **T3, T4, T2:** register a recomputer for each replayable rule and write snapshots with `replay.encode_inputs`, `encode_array` and `hash_inputs`.

### 5. Deviations from the design
- `why-heard` uses LEFT JOIN `config_cohort` (9.4 has an inner join) and maps the default cohort through `coalesce(cohort_key, cohort_id)`, because M0 stores `cohort_key` as NULL for 'default'.
- I added `controller/api/views.py` (the read models) next to `app.py`, which is not in 11.1. I also added the API's own least-privilege refusal.
- I added alert codes `SIM_UNREACHABLE` (from 8.4 and `alert_get_retry_page_s`) and named the digest items. CREDITS_BELOW_RESERVE uses W = 13 K, without the tight-gate term. INGEST_STALLED approximates "listed but not committed for 5 minutes" as listed above ingested and no commit for 5 minutes.
- `/supervisor` "upcoming" returns `next_routine_slot: null`; that value comes from governance timing (T2) and is not in the store.
- The variants use public_01 and public_02 only. public_03 (63 s per baseline) is the load test and needs no private variants.

### 6. Known gaps and risks
- **Replay of real decisions** waits on the registrations above. Discovery imports every module in the learning, incidents, governance and planner packages, so a module with import-time side effects would run them.
- **The fixture database follows the design's conventions**, not real writer output. Explain and the views need re-checking against a finished public_02 run (the M7 acceptance: `why-changed --workflow ks_cancel --at "D3 14:00"`).
- **The M0 contract tests use the fixed port 8700**, so they can collide if several tracks run them at once.
- **Grade-mode controller runs in `run_matrix.sh`** were only exercised with the naive example; the real `run.sh` and compose stack is M1.
- **Two session fixtures:** tests/audit and tests/obs each build their own fixture schema, which works but is redundant.
